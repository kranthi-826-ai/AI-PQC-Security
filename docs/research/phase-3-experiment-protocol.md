# Phase 3 Experiment Protocol

## Objective

Build a reproducible threat-classification pipeline that produces an explainable
risk input for the later adaptive security policy engine. Phase 3 evaluates the
AI component; it does not yet implement PQC policy execution.

## Datasets

1. **Primary benchmark:** official `UNSW_NB15_training-set.csv` (175,341 rows)
   and `UNSW_NB15_testing-set.csv` (82,332 rows).
2. **System-specific evaluation:** versioned, de-identified events generated by
   this project's Auth, Gateway, Business, and Monitoring services. These data
   must never be mixed into the public benchmark test set.
3. **Candidate microservice benchmark:** P03 data only after its source, license,
   schema, and collection conditions are documented.

The official UNSW page states that academic use is free with citation and that
the dataset contains nine attack families plus normal traffic.

## Leakage controls

- The official test file is held out from preprocessing, feature selection,
  tuning, calibration, and threshold selection.
- A stratified validation partition is created only from the official training
  file with seed `42`.
- Imputation, encoding, scaling, and feature selection are fitted on training
  data inside a scikit-learn pipeline.
- `id` is excluded. `attack_cat` is excluded when predicting binary `label`.
- Duplicate analysis and any removal policy are recorded rather than silently
  changing the benchmark.
- The test set is evaluated only after model selection on validation metrics.

## First experiment

- Task: binary normal-versus-attack classification (`label`).
- Baseline: class-balanced logistic regression.
- Candidate: class-balanced random forest suitable for a 16 GB laptop.
- Model-selection metric: validation macro F1.
- Required reporting: accuracy, macro and weighted precision/recall/F1,
  attack-class precision/recall/F1, ROC-AUC, confusion matrix, false-positive
  rate, training time, and per-sample inference latency.
- Repeatability: fixed seed, saved dependency versions, dataset hashes, command,
  configuration, and JSON results.

Multiclass attack-family classification and advanced neural/graph candidates
are later experiments, not shortcuts around the binary baseline.

## Model promotion rule

A candidate may be marked `candidate` only when it beats the baseline validation
macro F1 and does not materially worsen attack recall, false-positive rate, or
inference latency. It becomes `selected` only after held-out test evaluation and
recorded review. Model files remain generated artifacts and are not committed.

## MLOps use

MLflow is used locally and free of charge for parameters, metrics, artifacts,
and run comparison. Later phases will add model versioning, inference monitoring,
data-drift checks, and controlled promotion/rollback. MLOps supports the
research lifecycle; it is not itself the threat detector.
